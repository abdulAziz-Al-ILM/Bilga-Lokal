# Book library metadata — 2026-11-15

This is the library foundation, not a complete reading/knowledge-card product. Existing private Book records, title, characters, chapters, chapter history and positional bookmarks remain intact. Reading sessions, cover ownership, knowledge cards, stable chapter references and review scheduling remain required.

Optional root `libraryVersion: 1` and `library` metadata add author, description, genre, categories, tags, shelves, publisher, publication year, ISBN, language, reading status, start/finish dates, total/current pages, rating and favorite. Legacy reads supply unknown/empty metadata without rewriting a row or inventing reading dates, authors or completions. New explicit creation starts with Planned status. Editing metadata deep-copies the payload and preserves chapters/history/bookmark and unrelated fields. Shared RecordStore validates metadata before any persistence, indexing or backup merge.

Status is unspecified/planned/reading/completed/paused/abandoned. Year/page/rating/date constraints and canonical date order are validated. Labels are bounded and deduplicated without case sensitivity; publication/pages/rating may remain unknown. Description whitespace is retained. Future metadata versions and malformed values fail closed. ISBN validation checks format and checksum, not assignment, title identity or ownership. ISBN-13 prefix and alternating-weight modulus rules follow the [International ISBN Agency](https://www.isbn-international.org/index.php/node/10); legacy ISBN-10 and X follow the [US ISBN Agency FAQ](https://www.isbn.org/faqs_general_questions). No catalogue lookup, copyrighted content download or sample library seeding occurs.

`BookLibraryStore` fetches bounded thin summaries, normally 50 rows per UI page, with FTS prefix search, status/favorites/shelf/tag/category filters and fixed updated/title/author sort choices. Full chapter payloads load only when opening/editing a record. Search previews include author/description while full FTS already indexes validated payload content. Generation checks prevent delayed filter loads from replacing newer search state. SQL binds filter values, including punctuation and quote characters.

The editor has explicit Save, fresh Core authorization and revision checks. Failed/stale writes retain the form; later authorization permits an explicit retry. Source reader and readable export include metadata and full chapter content without writing. Attachments preserve owner filtering and allow injected fixture stores. Local portable backup remains idempotent and retains metadata and history. No dependency, Notes/Tasks schema or backup framing change is introduced by this compatible payload extension. Notes DB remains 16, Tasks DB 13; Book-only portable content remains Notes 13, and Finance account-bearing snapshots use Notes 14.

Host/model/encrypted/device evidence is scoped in the dated reports. Screenshots marked DEMO use separate encrypted temporary fixtures in the isolated Review package, not the owner's library.

# Known limitations

Overall product is IN PROGRESS. The master spec acceptance criteria are not yet met.

1. Rich-text Notes, checklists, links and formatting-preserving history/backups are implemented and host tested. Tablet rich editing/save/reopen/backup/rotation tests pass. Supported file-import workflows and the complete Notes interaction audit remain required.
2. Occurrence-safe task recurrence is implemented through UI, storage, backup and native notification actions. Custom selected weekdays, intervals, end dates, month-end recovery and DST checks pass. One-level subtasks/checklists, progress and independent task duplication now work, including recurrence, search, reader/export and backup. Subtasks have titles/completion, with no separate dates/reminders. Custom task templates now work through create/edit/delete/snapshot/application and backup. Projects now pass full host tests and the corrected 43-scenario tablet suite, including real nested-list/progress/status/conversion workflows. Task tags, calendar organization, sorting and bulk workflows still need completion.
3. On Tab16/API31, real quiet task notification delivery, snooze/re-delivery and native PendingIntent completion pass. Reboot/Doze/timezone, blocked permissions and other devices remain unverified. Standalone, habit and note reminders are incomplete. Android permissions and battery policies can delay delivery.
4. Journal still needs custom categories, calendar navigation, mood tracking and durable entry-history management. Public sharing remains disabled.
5. Planning uses original tasks and habits. A separate reminder timeline and durable note/task/journal relationships are not yet implemented. Large planner datasets have not been profiled.
6. FTS4 uses unicode61 token-prefix matching, ordered by recency. It is not semantic search or generative AI. Language-specific stemming, CJK segmentation, relevance ranking and tag-library-only result rows need improvement. Archived results require explicit inclusion; trashed content is excluded.
7. New purchases retain the recovered signed server-grant requirement. The Python verifier backend, Google lookup/acknowledgment adapter and hashed token ledger are implemented and host tested. A Play product, public licensing key, HTTPS deployment and pinned Ed25519 public key still require configuration and real purchase tests. Deployment and any paid hosting activation require separate authorization. An anonymous restore endpoint cannot prove ownership of a copied genuine receipt; device-bound grants do not remove that limitation. No financial infrastructure is activated. Trial works independently of Play availability. Real purchases are unverified.
8. Completely offline devices cannot learn of new refunds. Verified cached grants work offline; signed revocation is applied on later verification. Reinstall/clear-data cannot be reliably distinguished from first install without identity or tracking. No fingerprinting is used.
9. Read-only access uses a separate data browser, preserving the covered editor/navigation stack. Full access to historical deleted items remains through backups; the read-only browser excludes trash. Backup import requires active access and an explicitly confirmed merge; replacing existing records is not offered.
10. Local encrypted media backups are supported, but Drive currently declines media-bearing backups rather than silently omitting attachments. Streaming media to Drive remains required.
11. Existing device credential/biometric lock is retained. A separate app-specific PIN is not implemented. Database/attachment encryption depends on Android Keystore; uninstall/key loss requires a prior portable backup.
12. New UI translations in seven priority languages are drafts. New strings in other supported catalogs use English pending translation. Existing hardcoded startText UI still needs a full audit. Native-speaker verification has not occurred.
13. A current-source CI debug APK and host benchmark are verified. Tab16/API31 has 43 passing scenario cases plus 13 Notes widget and 46 task native checks. No signed release APK/AAB, release runtime benchmark or full interaction audit is certified. Measured debug cold Activity launch was 5930 ms; this does not meet or certify the release startup target. Signing keys were not replaced or copied.

# Google Play prerequisites checked 2026-11-09

These checks support release preparation. They do not certify store acceptance or substitute for a review of the final binary and Console configuration.

- Mobile new apps/updates currently require **target API 36+**. The pinned Flutter 3.47.8 Gradle extension declares target/compile 36, and Bilga inherits those values. The merged APK manifest must also pass the CI binary check. [Official target API requirements](https://support.google.com/googleplay/android-developer/answer/11926878).
- Billing Library 7's new-submission deadline was August 31, 2026, with its extension ending November 1, 2026. The recovered lock used Billing 7.1.1 and was therefore unsuitable for submission. Updated official packages to in_app_purchase 3.3.1 and in_app_purchase_android 0.5.5; the downloaded Android plugin explicitly declares **Billing 9.1.0**. [Official deprecation timeline](https://developer.android.com/google/play/billing/deprecation-faq), [Flutter package changelog](https://pub.dev/packages/in_app_purchase_android/changelog).
- The official 0.5 migration removes purchase-history lookup. Bilga uses active purchases (`queryPastPurchases` in the Flutter platform addition), not the removed native history API. Cache removal still requires authenticated revocation; an empty list or network outage does not erase paid access. [Flutter migration guide](https://github.com/flutter/packages/blob/main/packages/in_app_purchase/in_app_purchase_android/migration_guide.md).
- Verify and acknowledge completed purchases; pending payments do not unlock. Bilga's 40-day evaluation is app-managed and never represented as a subscription trial. [Official purchase integration guide](https://developer.android.com/google/play/billing/integrate).
- If the actual publisher is a personal developer account created after November 13, 2023, production access currently requires a closed test with at least 12 opted-in testers continuously for 14 days. The publisher's account type and eligibility were not supplied or verified. [Official personal-account testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465).
- Merchant registration support and consumer purchase availability are different checks. The 249-row ISO pricing sheet does not assert either. Verify the actual merchant account and each target market in Console. [Official supported registration locations](https://support.google.com/googleplay/android-developer/answer/9306917), [country-specific distribution requirements](https://support.google.com/googleplay/android-developer/answer/6223646).

The CI manifest gate checks package identity, target API, Billing version metadata and absence of microphone permission. Four Python tests verify that it rejects incompatible identities, API targets, obsolete billing, absent metadata and transitive microphone permission. Real manifest evidence is only available after a successful APK build.

Still required: actual account/merchant/product setup, tax/local currency approval, real billing acceptance, final privacy/Data Safety/content-rating declarations, device testing, signing compatibility and owner approval for publication. Recheck all policy deadlines at the eventual release date.
